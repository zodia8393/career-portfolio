2.1 자료 확보와 결합

  1. 기존 요청의 결과를 다시 조회

    불명확한 응답이 발생하면 후속 요청을 차단하고 이전 요청번호로 외부 처리 결과를 조회했습니다.

  2. 조회한 상태를 기록용으로 구성

    잔고·전략 상태를 조회해 스냅샷을 만들고 HTML·JSON 기록으로 변환했습니다. 이 기록 경로는 주문·매도 미리보기·확인값 생성과 분리했습니다.

  3. 공개 자료는 비식별 요약으로 제한

    포트폴리오에는 실제 계좌·금액·거래 원문 대신 복구 단계 요약과 더미 객체 기반 시험 결과를 사용했습니다.

2.2 정제·결측·제외 기준

  1. 불명확한 응답을 별도 처리

    취소 여부의 빈 문자열을 성공·실패로 임의 확정하지 않고 검토가 필요한 상태로 분류했습니다.

  2. 기존 검사와 중복 확인 유지

    필드 존재·타입 검사는 유지하면서 빈 문자열 예외를 보완하고, 확정 결과가 내부 기록에 한 번만 반영되는지 확인했습니다.

  3. 기록 대상 정리

    조회 화면에는 실제 보유 항목을 기록하고 수량 0인 목표 항목을 제외했습니다. 공개 설명에는 식별·거래 정보를 포함하지 않았습니다.

3.1 분석 방식의 선택 근거

  1. 재요청보다 결과 조회를 먼저 한 이유

    응답이 불명확해도 외부에서는 이미 처리됐을 가능성이 있어, 같은 작업을 다시 요청하면 중복 실행 위험이 있었습니다.

  2. 외부 결과와 내부 상태를 함께 본 이유

    외부에서 확정된 결과와 내부 기록을 맞춰야 미확정 상태를 복구하고 동일 결과의 중복 반영을 확인할 수 있었습니다.

  3. 조회·기록 기능을 분리한 이유

    상태를 확인하거나 보관하려고 화면을 열 때 주문 관련 동작이 함께 실행되지 않도록 기능의 경계를 분명히 했습니다.

3.2 분석·구현 절차

  1. 상태 복구 절차 구현

    응답 해석 → 후속 요청 차단 → 기존 결과 조회 → 내부 기록 반영 순서로 처리했습니다.

  2. 조회 전용 기록 페이지 구현

    조회한 스냅샷만 렌더링하는 HTML 페이지와 JSON 경로를 추가하고 실행 기능과의 분리를 확인했습니다.

  3. 회귀 검사와 복구 경로 보관

    같은 응답 유형과 기존 기능을 재검사하고 이전 코드·설정을 보관했습니다. 대시보드 테스트와 전체 시스템 테스트의 범위를 구분했습니다.

6.1 결과의 해석

6.2 분석·개발에서 얻은 판단

  • 외부 API 오류 대응에는 요청 식별자와 상태 대조 절차가 필요합니다

    응답이 불명확할 때 같은 작업을 즉시 다시 요청하면 중복 실행 가능성이 생깁니다. 기존 결과를 조회할 식별자와 미확정 상태의 처리 규칙을 갖춰야 복구 판단을 내릴 수 있습니다.

  • 상태를 관찰하는 경로를 분리하면 점검 범위가 명확해집니다

    조회·기록 화면이 실행 동작을 호출하지 않도록 분리하면 상태 확인과 작업 실행을 각각 검증할 수 있습니다. 이 경계는 다른 외부 API 연동 도구에도 적용을 검토할 수 있습니다.

세부 검산·평가 기록 펼치기

다시 요청하기 전에 이전 처리 결과부터 확인

2026년 7월 20일 외부 API의 취소여부 필드가 빈 문자열로 반환되면서 기존 요청을 검토 필요 상태로 남기는 문제가 발생했습니다. 신규 요청을 다시 보내거나 기록을 수동으로 삭제하지 않고 기존 식별자를 조회해 실제 결과를 확인했습니다.

문자열 필드의 존재와 타입 검사는 유지하면서 실제 응답 규칙에 맞게 빈 문자열 처리를 보완했습니다. 확정 결과가 한 번만 반영되고 감사 기록이 중복되지 않는지 확인하고, 같은 유형의 응답을 회귀 테스트에 추가했습니다.

S3에 둔 버전별 산출물과 설치 파일의 해시를 대조하고 이전 코드·실행 설정을 보존했습니다. 같은 날 별도 배포에서는 전체 테스트 481개 통과를 확인했으며, 이 장애 한 건의 테스트 개수와는 구분합니다.

개인 운영환경의 장애 복구 사례입니다. 실제 요청을 실행하지 않는 기록 조회 데모이며 금융정보·투자성과는 공개하지 않습니다.

데모에서 확인하는 내용

복구 과정의 각 단계를 선택하면 당시 확인한 상태와 판단을 읽을 수 있습니다. 실제 금융 API 연결이나 주문 기능이 없는 설명용 재생 화면입니다. 로그 원문 대신 비식별한 사건 요약만 사용합니다.

01

2026.07.20 · 문제 확인

빈 응답 값으로 상태 확정이 멈춤

외부 API가 취소 여부를 빈 문자열로 반환하면서 내부 처리가 검토 필요 상태로 남았습니다. 필드가 존재해도 내부 검사와 실제 응답 규칙이 다를 수 있음을 확인했습니다.

확인한 결과성공·실패를 임의로 확정하지 않고 이전 요청의 실제 결과를 확인해야 하는 상태로 분류했습니다.

02

후속 요청 차단

재요청 전에 기존 결과 조회

같은 작업이 이미 처리됐을 가능성이 있어 신규 요청을 차단했습니다. 이전 요청번호를 사용해 외부 처리 결과를 다시 조회했습니다.

확인한 결과기록을 삭제하거나 동일 작업을 재전송하지 않고 확인된 결과로 복구할 기준을 확보했습니다.

03

수정·상태 복구

응답 예외를 반영하고 중복 저장 확인

필드의 존재와 타입 검사는 유지하면서 빈 문자열을 처리하도록 보완했습니다. 확인한 결과를 내부 상태와 맞추고 중복 반영 여부를 검사했습니다.

빈 응답 값 확인후속 요청 차단이전 결과 조회내부 기록 복구재검사·버전 보관

확인한 결과불명확하게 남은 처리 상태를 복구하고 결과가 한 번만 기록되는지 확인했습니다.

04

검증·버전 보관

같은 오류와 기존 기능 재검사

동일한 응답 유형을 검사 항목에 추가하고 기존 기능도 다시 확인했습니다. 수정본과 이전 코드·설정을 보관해 되돌릴 경로를 유지했습니다.

확인한 결과최종 산출물은 예외 처리 수정, 상태 복구 기록과 검증 근거입니다. 공개 화면에는 비식별한 단계 설명만 제공합니다.

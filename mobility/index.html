01 / 진행 과정

수집·변환·품질 검사를 실행 단위로 연결

Airflow가 15분 수집과 재실행을 조정합니다. 같은 원천 시각의 응답을 다시 받아도 지역·도로 링크·시각으로 구성한 키를 사용해 중복 적재를 방지합니다. 원문과 변환 산출물에는 실행 단위의 해시와 행수 검증 기록을 남깁니다.

원천에 없는 교통량이나 기준속도는 임의로 만들지 않습니다. dbt 검사, 원천과 적재 행수, 변환 산출물 확인이 통과해야 게시 가능 상태로 바뀌도록 구성했습니다.

서울 API원문 보존Parquet 변환PostgreSQL·dbt게시 가능 판정

Airflow·dbt·PySpark는 로컬 Docker 실행입니다. 분산 Spark나 관리형 Airflow 운영 실적으로 확대하지 않습니다.

02 / 진행 과정

로컬 예약 실행과 AWS 확인 범위를 구분

예약 실행 기록은 2026년 8월 31일 로컬 Docker 환경의 누적 115,570행과 최근 10회 성공을 보여줍니다. 같은 날 이후 AWS 기록의 116,025행은 별도 확인 시점의 값이며 두 수치를 하나의 같은 시점으로 섞지 않습니다.

AWS에서는 S3 객체 적재, 이미지 저장소와 상태 지표를 구성하고 Fargate 작업이 이미지 읽기·S3 일부 읽기·CloudWatch 기록을 수행한 뒤 종료 코드 0으로 끝나는지 확인했습니다. 상시 ECS 서비스나 AWS에서 Airflow·Spark를 운영한 결과는 아닙니다.

웹 데모는 날짜가 고정된 실행 기록을 조회합니다. 현재 수집 상태를 보여주는 실시간 운영 화면이 아닙니다.

실패와 재실행

수집 오류는 retry·timeout과 실행 기록으로 확인하고, 같은 실행을 반복할 때 중복 키를 검사합니다. 원본 객체, 행수 대조, dbt 결과, 변환 산출물 검사가 통과하지 않으면 게시 상태가 READY가 되지 않도록 구성했습니다. 데모에는 확인된 성공 기록만 표시하며 임의의 장애 이력을 생성하지 않습니다.

실행 환경

공개 저장소의 README에 Docker Compose 실행, API 키 설정, 검증 명령과 운영 범위를 설명합니다. 데모 열람에는 API 키가 필요하지 않습니다. 직접 수집을 재현할 때는 사용자 본인의 서울 열린데이터광장 키와 로컬 실행환경이 필요합니다.

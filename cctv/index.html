초록

고속도로 CCTV 차량 이미지와 라벨을 정리하고 MobileNetV4 학습·튜닝을 수행했다. 직접 학습한 모델과 별도의 EnsembleClassifier 평가를 구분해, 966장 평가 자료의 혼동행렬·차종별 표본·F1을 분석했다. 별도 평가는 전체 정확도 82.61%였지만 소형화물의 재현율은 약 46.1%로 나타났다. 학습곡선·분류 평가·영상 실행을 서로 다른 근거로 제시하고 현장 성능으로 일반화하지 않았다.

주요어 MobileNetV4 · PyTorch · 혼동행렬 · 불균형 표본 · 모델 평가

연구·개발 목적

경동고속도로 CCTV 차량의 검출·추적·7종 분류를 위한 라벨링·학습·평가 파이프라인을 구축하고, 차종별 오류와 평가 자료의 적합성을 확인한다. [1] [2]

이 사례에서 다루는 문제

고속도로 CCTV 차량을 7개 차종 코드로 분류하는 파이프라인에서, 학습 자료의 분리와 차종별 오분류를 어떻게 검증할 수 있는가?

문서에 기재된 목적과 수행 내용을 바탕으로 질문을 요약했습니다. 원문의 직접 인용은 아닙니다.

2.1 자료 확보와 결합

  1. 이미지와 라벨 연결

    영상에서 추출한 차량 이미지와 정답 라벨을 연결해 학습·검증·평가 자료를 준비했습니다. 원본 영상의 촬영·반입 경로는 공개 작업 기록에 제시돼 있지 않습니다.

  2. 평가용 파일 구성 점검

    기존 4,336행 평가 준비 파일의 해시 불일치와 외부 자료 2,542행 혼입을 확인하고, 별도 정리한 966장 평가 자료의 파일 존재·정보를 점검했습니다.

  3. 실행별 결과 보관

    직접 학습한 MobileNetV4의 가중치, 별도 모델 평가, 학습곡선과 영상 실행 로그를 서로 다른 실행 기록으로 구분했습니다.

2.2 정제·결측·제외 기준

  1. 파일과 라벨 점검

    이미지 존재·해시·정답 연결을 확인하고 학습·검증·평가 대상을 구분했습니다. 파일 무결성 검사와 학습·평가 중복 검사는 별개의 확인 사항입니다.

  2. 차종별 표본 분포 확인

    표본이 많은 차종과 희소 차종을 구분했습니다. 평가 표본이 1장인 이륜차는 일반적인 성능 판단에서 제한을 표시했습니다.

  3. 학습 입력과 설정 구성

    좌우 반전·부분 잘라내기·밝기 변화와 클래스별 가중 손실을 적용하는 학습 설정을 구성했습니다.

3.1 분석 방식의 선택 근거

  1. 이미지와 정답을 함께 사용한 이유

    분류기를 학습하고 어떤 차종을 다른 차종으로 혼동하는지 확인하려면 이미지별 정답이 필요했습니다.

  2. 평가 자료를 별도로 확인한 이유

    누락·변경·외부 자료 혼입이 있는 상태에서는 평가 결과의 대상부터 불명확해집니다. 파일 구성과 클래스별 표본을 먼저 확인했습니다.

  3. 모델·영상 실행 기록을 나눈 이유

    이미지 분류 점수와 영상에서 검출·추적이 동작하는지는 서로 다른 검증 대상이며, 모델 계보가 확인되지 않은 결과를 개선율로 연결할 수 없었습니다.

3.2 분석·구현 절차

  1. 분류기 학습·조정

    MobileNetV4 전체 학습과 기존 가중치를 불러와 특징 추출부를 고정하고 분류부를 조정하는 경로를 구성했습니다.

  2. 별도 평가의 오류 분석

    EnsembleClassifier의 혼동행렬로 전체 정확도와 차종별 정분류·오분류·F1을 함께 확인했습니다.

  3. 영상 동작 별도 확인

    100프레임 처리와 추적번호 기준 대상을 확인했습니다. 차량 단위 정답이 없는 영상 시험은 실행 확인 범위로 정리했습니다.

코드 구성과 구현 근거

이미지·정답 준비, 학습 설정, 평가 결과 해석을 구분해 기록했습니다. 평가 JSON의 정답 차종별 행을 읽으면 전체 점수와 차종별 오류를 따로 검산할 수 있습니다.

공개 평가 JSON으로 오류 건수 검산

import json

with open("model-evaluation.json", encoding="utf-8") as f:
    metrics = json.load(f)["metrics"]
small_truck = metrics["confusion_matrix"]["T3"]
support = sum(small_truck.values())
correct = small_truck["T3"]
as_medium_truck = small_truck["T4"]
assert (support, correct, as_medium_truck) == (76, 35, 19)

공개된 평가 JSON을 같은 폴더에 저장하면 실행할 수 있는 검산 예시입니다. 모델 학습 코드가 아니라 별도 평가 결과를 읽는 코드입니다.

그림을 읽는 기준

자료 구성·모델·평가 시점이 다른 점수를 비교해 개선율을 만들지 않는다. 17 epoch 곡선은 별도 fine_tune_v4 실행 기록이다.

06논의와 한계

6.1 결과의 해석

전체 정확도만으로는 소형화물 분류의 약점이 드러나지 않습니다

별도 EnsembleClassifier 평가는 966장 중 798장을 맞혀 정확도 82.61%였지만, 소형화물은 76장 중 35장만 정분류해 재현율이 46.1%였습니다. 소형화물 19장은 중형화물로 분류됐으므로 해당 차종의 집계에는 오분류 영향을 따로 점검해야 합니다.

희소 차종의 점수는 표본 수와 함께 읽어야 합니다

이륜차 평가 표본은 1장뿐입니다. 이 자료의 F1이 0이라는 값만으로 이륜차 전반의 성능을 판단할 수 없습니다. 파일 확인이 끝났더라도 차종별 성능을 평가할 만큼 표본이 충분한지는 별도 문제입니다.

6.2 분석·개발에서 얻은 판단

  • 다음 개선은 오류가 집중된 차종과 평가 자료부터 시작할 수 있습니다

    소형·중형화물 사이의 혼동 사례를 모아 정답 라벨과 촬영 조건을 점검하면 추가 데이터·모델 개선의 후보를 구체화할 수 있습니다. 현재 결과만으로 혼동 원인이 라벨인지 영상 조건인지 모델인지 확정하지는 않습니다.

  • 차종 통계에 쓰려면 차량 단위 평가가 추가로 필요합니다

    이미지 분류가 맞는지와 영상에서 차량을 빠뜨리거나 중복 집계하지 않는지는 다릅니다. 사용 목적이 차종별 교통량 집계라면 분류 성능과 검출·추적 성능을 함께 평가해야 합니다.

세부 검산·평가 기록 펼치기

평가 전에 데이터의 구성부터 점검

데이터 준비에서는 영상에서 추출한 차량 이미지와 라벨을 연결하고 학습·검증·평가 대상을 구분했습니다. 평가 준비 점검에서는 기존 4,336행 파일의 해시가 일치하지 않고, 그 안에 외부 자료 2,542행이 섞여 있음을 확인했습니다.

별도 정리한 966개 평가 자료는 파일 해시와 이미지 존재를 확인할 수 있었습니다. 다만 희소 클래스의 표본 부족이 남아 있어, 이를 서비스 적용 여부를 판단할 수 있는 충분한 평가 자료로 취급하지 않았습니다.

파일의 누락·변경 여부와 학습 자료와의 중복 여부는 다른 검사입니다. 이 자료만으로 현장 적용 성능을 확정하지 않았습니다.

분류기 학습과 미세조정 기록

학습 코드에는 좌우 반전·부분 잘라내기·밝기 변화와 클래스별 가중 손실이 구현돼 있습니다. MobileNetV4 전체 학습 후에는 기존 가중치를 불러와 특징 추출부를 고정하고 분류부를 조정하는 경로를 구성했습니다. 해당 학습의 best·last 가중치 파일이 남아 있습니다.

아래 곡선은 별도 분류기 실행 fine_tune_v4의 17개 epoch 기록입니다. 훈련 손실이 감소해도 검증 손실은 같은 방식으로 줄지 않는 구간이 있어, 훈련 결과만으로 판단하지 않았습니다. 이 곡선은 MobileNetV4나 6월 평가 모델의 학습곡선으로 제시하지 않습니다.

곡선은 별도 fine_tune_v4 실행 기록이며 MobileNetV4·6월 평가 모델의 곡선이 아닙니다. 자료 구성이 다른 회차의 점수는 직접 비교하지 않았습니다.

어떤 차종을 잘못 구분하는지 확인

2026년 6월 16일 EnsembleClassifier 평가의 혼동행렬을 기준으로 각 클래스의 정분류·오분류를 확인했습니다. 전체 정확도와 클래스별 F1을 함께 보면 표본이 많은 클래스의 성능이 전체 지표에 미치는 영향을 구분할 수 있습니다.

T3의 재현율은 약 46.1%이며 T4로 분류한 사례가 19개입니다. T13은 평가 표본이 1개뿐이므로 F1이 0이라는 값만으로 일반적인 성능을 판단할 수 없습니다. 해당 평가는 적용 한계를 설명하는 자료이며 최종 현장 성능으로 확대하지 않습니다.

966개 평가와 4월 학습 실험 사이의 모델 계보가 모두 확인된 것은 아닙니다. 이 수치를 특정 튜닝의 개선 효과로 연결하지 않았습니다.

모델 점수와 영상에서의 동작을 분리

차량 이미지 분류가 맞는지와 실제 영상에서 검출·추적이 안정적으로 이어지는지는 다른 문제입니다. 영상 시험에서는 처리 프레임, 추적 대상, 차종 관측과 로그의 일치 여부를 확인했습니다.

10초 구간을 10fps로 구성한 100프레임 시험은 6.339초에 처리됐습니다. 사람이 확인한 차량 단위 정답이 없으므로 이 기록은 실행 확인에 사용하며, 속도 정확도나 현장 차종 분포 정확도로 해석하지 않습니다.

영상의 실제 차량 수·차종을 사람이 확인한 정답은 없어 현장 정확도를 계산하지 않았습니다.

실험 비교에서 지킨 범위

회차별 학습 기록에는 표본 구성과 클래스 포함 여부가 달라진 실험이 함께 있습니다. 서로 다른 평가 자료의 점수를 빼서 성능 향상률을 만들지 않았습니다. 모델 이름·데이터 분할·평가 시점이 일치하는 비교만 개선 근거로 사용할 수 있습니다.

현재 자료의 한계

4월 분류기 학습 실행과 MobileNetV4 가중치는 확인되지만, 모든 모델에 대한 학습곡선과 6월 평가까지의 완전한 계보는 확인되지 않습니다. 일부 학습 코드의 분할은 이미지 경로 단위이므로 영상·차량 단위 누수까지 해소됐다고 주장하지 않습니다. 평가 표본과 적용 범위의 한계를 남겨 두었습니다.

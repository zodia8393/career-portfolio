초록

단일 매장의 네이버 플레이스 방문자 리뷰를 수집하고, 기존 답글을 참고한 AI 초안 생성·품질 검사·사람 검수·등록 확인을 연결했다. 최초 수집 기록은 리뷰 255건과 기존 답글 223건이며, 2026년 9월 4일 일괄 등록 단계에서는 신규 31건과 앞선 시험 등록 1건을 합친 32건의 DB 상태·원격 확인 이력이 일치했다. 실제 사용자 피드백을 받아 답글의 반복적 표현과 분량 기준, 미처리 리뷰 수집, 탈락 초안 재작성, 처리 날짜 범위를 개선했다. 검사 규칙 변경은 경계값·회귀 테스트로 확인하고, 실제 등록과 원격 대조까지 수행한 개발 사례다.

이 사례에서 다루는 문제

리뷰 수집부터 AI 답글 등록까지 구현한 뒤, 실제 사용자의 말투·분량·처리 범위 요구를 어떻게 시스템 동작에 반영했는가?

문서에 기재된 목적과 수행 내용을 바탕으로 질문을 요약했습니다. 원문의 직접 인용은 아닙니다.

  1. 초기 구현의 수집·생성·검수·등록 흐름을 실제 매장 리뷰에 적용할 수 있는가? [1] [5]
  2. 답글의 말투·분량에 관한 사용자 요구를 생성 지침과 검증 규칙에 함께 반영할 수 있는가? [8] [9]
  3. 수집 누락·재작성 실패·처리 범위 문제를 수정하고, 재발 여부를 테스트와 실행 기록으로 확인할 수 있는가? [10] [11] [6] [12]

참고 답글 검색은 어떻게 구현했는가?

한글·영문·숫자만 남긴 텍스트에서 연속 3글자 조각의 빈도를 만들고 코사인 유사도로 과거 리뷰를 정렬한다. 유사 리뷰에 달린 기존 답글을 생성 예시로 제공하며, 내용 해시와 알고리즘 버전으로 특징을 재사용한다. 신경망 임베딩이나 모델 추가 학습을 수행한 것으로 표현하지 않는다. [3]

리뷰의 수집·생성·검수·등록 상태를 분리하고, 이전 답글을 검색해 참고한 뒤 초안을 검사한다. 통과 초안만 등록 대기로 보내며 검수·오류 상태와 재시도 이력을 보존한다.

  1. 최신순 수집과 중복 방지

    최신순 선택을 확인한 뒤 과거 리뷰를 수집한다. 완료 표시 전에는 생성을 시작하지 않으며, 후속 증분 수집은 이미 아는 리뷰 3개를 만나는 조건으로 종료한다.

  2. 말투 참조와 구조화된 생성

    기존 답글의 지문이 바뀌면 말투 프로필을 갱신한다. 유사한 과거 리뷰의 답글을 예시로 삼아 JSON 형식의 초안과 근거 항목을 생성하고, 리뷰 원문은 실행 지시와 분리한다.

  3. 품질 검사와 재작성

    공백 포함 500자 상한·공백 제외 300자 하한, 원문 근거, 반복 표현·개인정보·유사도를 검사한다. 실패 이유와 이전 초안을 보존해 구체적으로 수정하며, 통과하지 못하면 미게시 상태를 유지한다.

  4. 사람 검수와 날짜 범위

    낮은 별점과 민감 내용은 사람이 확인할 상태로 보낸다. 승인·수정·재생성 API를 제공하고 재작성해도 기존 검수 필요 표지를 유지한다. 날짜 제한은 DB의 작업 선택 단계에도 적용한다.

  5. 등록과 원격 대조

    행 잠금으로 처리 대상을 가져오고 등록 직전 기존 답글을 확인한다. 다른 답글이 있으면 보존·동기화하고 건너뛴다. 등록 후 원격 표시를 확인해야 POSTED로 기록하며 생성 실패와 등록 실패를 구분한다.

  6. 실제 사용자의 피드백 반영

    말투·분량·수집 누락·재작성·처리 범위 요청을 구분해 생성 지침, 검사 규칙, 수집기, DB 상태 관리에 반영했다. 경계값·회귀 테스트와 운영 결과를 각각 확인했다.

사용자 피드백 1 · 자연스러운 말투와 유연한 분량

자연스러운 답글을 원한다는 요청에 따라 반복 감사·과장 비유·장식적 표현·긴 문장을 검사 항목으로 추가했다. 내용이 없는 리뷰에는 메뉴나 방문 상황을 만들어 넣지 않도록 생성 지침도 바꿨다. [8] [9]

450자를 약간 넘는 답글도 허용해 달라는 요청은 권장 분량과 절대 상한의 분리로 반영했다. 기존에 길이 때문에 탈락한 484자 초안이 500자 상한 안에서 통과한 기록을 확인했다. 이는 해당 초안 검증 결과이며 사용자 만족도 점수는 아니다. [8] [9]

사용자 피드백 2 · 빠진 리뷰와 반복 실패를 추적

미처리 리뷰가 더 있다는 사용자 지적으로 신규 수집 10건을 전체 잔여 건수처럼 보고한 오류를 정정했다. 수집 도중 공유 ID 집합이 바뀌어 조기에 종료되는 원인을 수정하고 회귀 테스트와 운영 반영까지 이어갔다. [10] [11]

탈락 사유를 반영해 다시 작성해 달라는 요청에 따라 실패한 초안·검사 항목·수정 지시를 시도마다 보존했다. 길이 부족분, 긴 문장, 반복 표현을 구체적인 재작성 입력으로 전달하고 재실행 때도 마지막 실패 초안부터 이어갔다. [10] [11]

사용자 피드백 3 · 요청한 범위와 승인 절차 유지

9월 6일 이후 리뷰만 처리해 달라는 요청에 맞춰 날짜 미상과 이전 날짜를 대상에서 제외했다. 당시 이전 날짜의 신규 등록은 0건이었고, 검수 보류 1건은 사용자가 확인·승인한 뒤에만 등록했다. [12] [7] [6]

최적화에서는 검사에 통과하는 저장 초안을 재사용하고, 길이만 부족하면 필요한 부분을 보완했다. 기존 답글이 이미 등록된 경우에는 덮어쓰지 않고 동기화해 건너뛰었다. 9월 21일 개선 배포 기록의 회귀 검증은 72개 통과였다. [12] [7] [6]

실제 리뷰 등록과 원격 대조를 수행한 뒤 사용자 피드백을 말투·분량 검사, 수집 누락 수정, 실패 초안 재작성과 날짜 범위에 반영했다. 구현 변경은 테스트와 해당 실행 기록으로 확인했다.

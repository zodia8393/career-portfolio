초록

프로젝트별 제작기의 공통 도로·입출력·Office 기능을 조사해 공통 모듈에 연결했다. 공통 기본값·프로젝트·작업 설정을 단계적으로 합성하고 필수 입력을 실행 전에 검증하도록 구성했다. 대표 업무의 경로·자료 재생성과 기존 최종본 33개의 내용 지문을 대조한 뒤 공용 DRT 서비스에 반영했다. 업무 고유 알고리즘과 과거 독립 실행파일까지 자동 변경되는 것으로 일반화하지 않았다.

01연구 문제와 범위

지역·기간·입출력 차이를 설정으로 관리하면서 공통 기능의 수정과 결과 재생성을 일관되게 유지할 수 있는가?

작업별로 코드를 복사하면 도로 정책이나 파일 처리 수정이 일부 제작기에만 반영됩니다. 새 지역을 추가할 때 전역 경로를 바꾸는 구조도 반복 실행을 어렵게 했습니다.

자료의 근거

PC 공통 작업 목록과 재생성 검증, 2026.10.12 서버 배포 기록을 대조했습니다. 공개 페이지에는 내부 경로·접속 정보·인증정보를 포함하지 않습니다.

03분석·개발 방법

  1. 01공통·업무 고유 기능 구분
  2. 02설정 합성·입력 검증
  3. 03공통 구현 연결
  4. 04대표 결과 대조·서버 반영

공통 기본값 → 프로젝트 설정 → 작업 설정으로 합성하고 실행 전 필수 입력을 검사했습니다. 공용 기능은 한곳에서 관리하되 업무 고유 공식과 알고리즘은 각 프로젝트에 두었습니다.

  1. 공통 부분과 업무 고유 부분 구분

    기존 공용 기능을 먼저 확인하고 중복된 도로·입출력·보고서 기능을 연결했습니다. 지역 고유 분석 로직은 별도 모듈에 유지했습니다.

  2. 설정 검증을 실행 앞에 배치

    누락된 입력이나 잘못된 설정은 계산 전에 중단합니다. 새 수요 작업은 작업 루트를 인자로 받아 코드 복사와 전역 ROOT 변경을 없앴습니다.

  3. 결과와 캐시의 기준 고정

    도로 정책·구현이 바뀌면 코드 지문으로 행렬 캐시를 무효화합니다. 필수 입력은 캐시로 분류하지 않고 보존했습니다.

  4. 대표 업무 확인 후 배포

    축소 경로 비교와 Office·자료 재생성 검증을 거쳐 공용 서버에 반영했습니다. 기존 사용자 입력과 결과의 내용 지문을 대조했습니다.

04결과와 검증

표 2. 주요 결과와 평가 조건
평가·결과 항목확인한 값·산출물조건과 해석 범위
기능 검사공통 7개 / 기존 22개각 검사 범위를 구분.
축소 경로 대조3지역 × 2차종시종점 + 방문점 3개 조건의 행렬·경로 대조.
기존 결과 보존최종본 33개내용 지문 대조.
공용 서버 검증소천면 10개 시나리오2차종 × 1–5대. 기존 입력·선택·지도·최근 결과 보존.

도로 엔진, Office 처리, 한강버스 자료 입출력, TMAP 저장 기능을 공통 구현에 연결했습니다. 검증한 엔진을 공용 DRT 서비스에 배포하고 기존 입력·선택·최근 결과를 보존했습니다.

검증 조건과 관측 결과

  • 공통 기능 검사 7개·기존 기능 검사 22개를 확인하고, 3지역 × 2차종의 시종점+방문점 3개 축소 행렬·경로를 비교했습니다.
  • 기존 최종본 33개의 내용 지문을 보존했습니다. 한강버스 CSV 10개·Excel 11시트와 화성 LOS 검증을 공통 실행기로 연결했습니다.
  • 공용 DRT 서버에서 소천면 2차종 × 1–5대의 10시나리오를 재계산했습니다. 기존 입력·선택·지도·최근 결과의 해시 일치를 확인했습니다.

05시각화와 산출물

설정 합성, 실행 전 검사, 공통 기능 호출, 결과 대조의 흐름을 도식화했다. 실제 적용 업무와 확인한 범위를 표로 제시해 공통화 범위를 추적할 수 있게 했다.

그림을 읽는 기준

구조 검사와 내용·시각 검수는 다르다. 신규 업무 알고리즘이나 과거 EXE 전체를 설정만으로 대체했다는 의미가 아니다.

입력부터 결과까지, 변경 기준을 추적

  1. 설정 합성공통 → 프로젝트 → 작업
  2. 실행 전 검증필수 입력·범위·형식
  3. 공통 기능 호출도로·입출력·Office
  4. 결과 대조코드·입력 지문과 대표 업무

업무 고유 알고리즘은 프로젝트에 남기고 실제로 함께 쓰는 기능만 공통화했습니다.

06논의와 한계

6.1 결과를 읽는 기준

구조 검사와 내용·시각 검수는 다르다. 신규 업무 알고리즘이나 과거 EXE 전체를 설정만으로 대체했다는 의미가 아니다.

6.2 적용 범위와 한계

새로운 업무 알고리즘까지 설정만으로 대체할 수 있다는 뜻은 아닙니다. 업무 고유 구현은 별도로 필요합니다.

PPT의 ZIP/XML 검사는 구조 검사입니다. 시각적·내용 검수 완료를 의미하지 않습니다.

과거 배포 EXE와 별도 SHP API·워커 전체를 갱신한 작업은 아닙니다. 확인한 제작기와 공용 서비스에 한정합니다.

문제에서 결과까지

문제

작업별로 코드를 복사하면 도로 정책이나 파일 처리 수정이 일부 제작기에만 반영됩니다. 새 지역을 추가할 때 전역 경로를 바꾸는 구조도 반복 실행을 어렵게 했습니다.

선택

공통 기본값 → 프로젝트 설정 → 작업 설정으로 합성하고 실행 전 필수 입력을 검사했습니다. 공용 기능은 한곳에서 관리하되 업무 고유 공식과 알고리즘은 각 프로젝트에 두었습니다.

결과·활용

도로 엔진, Office 처리, 한강버스 자료 입출력, TMAP 저장 기능을 공통 구현에 연결했습니다. 검증한 엔진을 공용 DRT 서비스에 배포하고 기존 입력·선택·최근 결과를 보존했습니다.

구현 과정과 선택 이유

  1. 공통 부분과 업무 고유 부분 구분

    기존 공용 기능을 먼저 확인하고 중복된 도로·입출력·보고서 기능을 연결했습니다. 지역 고유 분석 로직은 별도 모듈에 유지했습니다.

  2. 설정 검증을 실행 앞에 배치

    누락된 입력이나 잘못된 설정은 계산 전에 중단합니다. 새 수요 작업은 작업 루트를 인자로 받아 코드 복사와 전역 ROOT 변경을 없앴습니다.

  3. 결과와 캐시의 기준 고정

    도로 정책·구현이 바뀌면 코드 지문으로 행렬 캐시를 무효화합니다. 필수 입력은 캐시로 분류하지 않고 보존했습니다.

  4. 대표 업무 확인 후 배포

    축소 경로 비교와 Office·자료 재생성 검증을 거쳐 공용 서버에 반영했습니다. 기존 사용자 입력과 결과의 내용 지문을 대조했습니다.

검증 근거

  • 공통 기능 검사 7개·기존 기능 검사 22개를 확인하고, 3지역 × 2차종의 시종점+방문점 3개 축소 행렬·경로를 비교했습니다.
  • 기존 최종본 33개의 내용 지문을 보존했습니다. 한강버스 CSV 10개·Excel 11시트와 화성 LOS 검증을 공통 실행기로 연결했습니다.
  • 공용 DRT 서버에서 소천면 2차종 × 1–5대의 10시나리오를 재계산했습니다. 기존 입력·선택·지도·최근 결과의 해시 일치를 확인했습니다.

해석과 적용의 범위

새로운 업무 알고리즘까지 설정만으로 대체할 수 있다는 뜻은 아닙니다. 업무 고유 구현은 별도로 필요합니다.

PPT의 ZIP/XML 검사는 구조 검사입니다. 시각적·내용 검수 완료를 의미하지 않습니다.

과거 배포 EXE와 별도 SHP API·워커 전체를 갱신한 작업은 아닙니다. 확인한 제작기와 공용 서비스에 한정합니다.
